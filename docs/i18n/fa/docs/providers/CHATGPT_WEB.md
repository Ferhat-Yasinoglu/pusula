# Providers — ChatGPT Web (Codex) (فارسی)

🌐 **Languages:** 🇺🇸 [English](../../../../providers/CHATGPT_WEB.md) · 🇩🇪 [de](../../../de/docs/providers/CHATGPT_WEB.md) · 🇹🇷 [tr](../../../tr/docs/providers/CHATGPT_WEB.md)

---

`chatgpt-web-codex` (با نام مستعار `cgpt-codex`) نوبتهای Codex Responses را از طریق یک
نشست احراز هویتشده در مرورگر ChatGPT برقرار میکند. این ارائهدهنده مستقل از ارائهدهنده عمومی
بازنشستهشده `chatgpt-web` است و از پیادهسازی دارای اعلان MIT در
`open-sse/vendor/codex-chatgpt-web/` استفاده میکند که تا commit نسخه بالادستی v4.0.7 با شناسه
`b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` بهروزرسانی شده است.

## بازنشستگی ارائهدهنده عمومی

شناسههای ارائهدهنده عمومی سابق، یعنی `chatgpt-web` و `cgpt-web`، دیگر عرضه نمیشوند، زیرا
منشأ پیادهسازی pre-key/proof-of-work آنها قابل تأیید نبود. درخواستهای صریح برای هر یک از این
شناسهها، از جمله شناسههای مدل دارای پیشوند اسلش و نامهای مستعار ذخیرهشده، پیش از هرگونه درخواست
به سرویس بالادستی، بهصورت بسته با HTTP `410` و کد **PROVIDER_RETIRED** شکست میخورند.

مهاجرت `168_retire_chatgpt_web.sql` اتصالهای منطبق با ارائهدهنده را بهصورت tombstone علامتگذاری
میکند و leaseهای فعال نشست آنها را نامعتبر میسازد. این مهاجرت تاریخچه اتصال و allowlistهای کلید
API را حفظ میکند؛ اما دسترسی جایگزینی را به allowlist اضافه نمیکند. ارائهدهنده Codex و
اتصالهای آن مشمول این بازنشستگی نمیشوند.

## پیشنیازها

- یک هدر کامل Cookie از نشست واردشده به ChatGPT؛
- Chrome یا Chromium بههمراه یک نشست گرافیکی یا نمایشگر Xvfb برای نصبهای npm، systemd و PM2؛
- هنگام استفاده از پروفایل Docker با نام `web`، سرویس داخلی Chromium از
  `docker-compose.yml`؛
- نسخه v0.0.13 از `tunnel-client` متعلق به OpenAI و یک رابط سفارشی ChatGPT برای ابزارهای محلی Codex.

تونل فقط برای نوبتهای دارای ابزار لازم است. تمام مسیرهای فهرستشده، از جمله `pro`، در صورت
پیکربندی تونل و رابط، میتوانند از همان قابلیت ابزار محلی محدود به نوبت استفاده کنند.

## راهاندازی داشبورد

1. ارائهدهنده **ChatGPT Web (Codex)** را باز کنید و یک اتصال اضافه کنید.
2. هدر کامل Cookie مربوط به ChatGPT، شناسه تونل، کلید زمان اجرا و نام کانکتور سفارشی را وارد کنید. راهاندازیهای جدید دارای قابلیت ابزار باید از کانکتوری تازهساختهشده با نام دقیق `Pusula Codex v2` استفاده کنند؛ Authentication باید روی None و Permissions روی Allow all actions تنظیم شود.
3. بررسی اتصال را اجرا کنید. Pusula یک Temporary Chat مبتنی بر مرورگر باز میکند و تشخیص میدهد که آیا Sol و Pro برای حساب در دسترس هستند یا خیر.
4. اتصال را ذخیره کنید. Pusula کوکی واردشده را با وضعیت ذخیرهسازی تأییدشده Playwright جایگزین میکند و آن را همراه با کلید زمان اجرا از طریق لایه انتزاعیِ رمزگذاریشده اعتبارنامهها ذخیره میکند.

کوکی خام پس از ذخیره موفق نگهداری نمیشود. هنگامی که نشست منقضی شد، اتصال را باز کنید، یک هدر کامل و تازه Cookie وارد کنید و بررسی را دوباره اجرا کنید. وضعیت doctor در کادر محاورهای ویرایش، مرورگر، وضعیت ذخیرهسازی، ورود به سیستم، Temporary Chat، تونل، کانکتور و رفتوبرگشت ابزار را بهصورت جداگانه گزارش میکند. برای خودکارسازی بهروزرسانی کوکیها هنگام تعویض نشستها، ابزار همراه را در [افزونه همگامسازی نشست مرورگر](../guides/SESSION-SYNC-EXTENSION.md) ببینید.

> هرگز یک کوکی واقعی، کلید زمان اجرا، وضعیت ذخیرهسازی یا توکن قابلیت را commit نکنید. مقادیر مربوط به آزمون و
> مستندات باید همیشه جاینگهدار باشند.

## مدلها و ترکیبها

مسیرهای ثابت مدل عبارتاند از:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna، تلاش کم
- `chatgpt-web-codex/think` — GPT-5.6 Luna، تلاش متوسط
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

یکی از آنها را مانند هر مدل دیگری به یک ترکیب اضافه کنید. برنامه Codex نام ترکیب را بهعنوان
`model` به endpoint معمول Responses، یعنی `/v1/responses`، ارسال میکند؛ هیچ endpoint جداگانه
Codex یا کلید تغییر حالت وجود ندارد.

حسابهای Free/Go مسیرهای Luna را ارائه میکنند. حسابهای دارای قابلیت Sol مسیرهای Instant تا
High را ارائه میکنند و حسابهای دارای قابلیت Pro علاوه بر آنها، Extra High و Pro را نیز
ارائه میدهند. هر مسیر دارای مدل backend و میزان تلاش استدلالی ثابتی است؛ یک میزان تلاش صریح و
متعارض در Responses، بهجای تغییر بیسروصدای حالت مرورگر انتخابشده، بهصورت بسته شکست میخورد.

نام رابط قدیمی `Codex Native` یا `Pusula Codex` را تغییر ندهید و از آنها مجدداً استفاده
نکنید. ChatGPT قرارداد عمومی MCP را بر اساس هویت رابط cache میکند، درحالیکه پل بهروزشده از
یک قرارداد مستقیم و جدیدِ توکن نوبت استفاده میکند. زمان اجرا این هویتهای قدیمی را رد میکند و
به یک رابط جدید `Pusula Codex v2` نیاز دارد.

## مدل امنیتی

- مسیر بومی به یک درخواست Responses، یک کلاینت شناختهشده Codex و تطابق شناسههای رشته و نوبت نیاز دارد.
- فضای کاری، سندباکس، سیاست تأیید و فهرست ابزارها از پوسته بومی Codex میآیند؛ متن آزاد پرامپت مرجع تعیینکننده آنها نیست.
- ChatGPT در هر نوبت فقط یک قابلیت کوتاهعمر دریافت میکند. کارگزار MCP فقط ابزارهایی را میپذیرد که Codex دقیقاً در همان نوبت ارائه کرده است.
- تأیید خودکار **فقط یکبار اجازه بده** تنها درخواست ابزار را به Codex بازمیگرداند. تصمیمگیری درباره تأیید و اجرا منحصراً بر عهده Codex است.
- پیش از نخستین خروجی، یک ترکیب ممکن است به هدف سازگار دیگری بازگردد. پس از آغاز خروجی، ارائهدهنده، مدل، اتصال و نوبت مرورگر تا پایان نوبت ثابت میمانند.
- کوکیها، کلیدهای زمان اجرا، وضعیت ذخیرهسازی و توکنهای قابلیت در پاسخهای ارائهدهنده یا گزارشهای درخواست ظاهر نمیشوند.

## VPS بدون نمایشگر و Docker

برای نصبهای npm، systemd و PM2، Pusula مسیرهای رایج Chrome و Chromium را شناسایی میکند.
همچنین میتوانید `CHATGPT_WEB_CODEX_CHROME_PATH` را تنظیم کنید. نوبتهای زمان اجرا عمداً از Chrome
در حالت دارای رابط گرافیکی استفاده میکنند، زیرا ChatGPT ساختار مرورگر واقعاً بدون رابط گرافیکی را رد میکند. بنابراین، یک میزبان بدون نمایشگر باید
Pusula را با یک نمایشگر خصوصی Xvfb اجرا کند؛ تنظیم مسیر Chrome بهتنهایی چنین نمایشگری فراهم نمیکند.

پروفایل `web` در Docker،‏ `chatgpt-web-codex-browser` را در شبکه داخلی Compose
راهاندازی میکند. کانتینر جانبی، Chrome را در حالت دارای رابط گرافیکی داخل Xvfb اجرا میکند؛ بنابراین به نمایشگر فیزیکی نیازی نیست. پورت CDP آن
روی میزبان منتشر نمیشود. حجم پروفایل محافظتشده مرورگر از حجم داده Pusula جدا است و
مرورگر حافظه اشتراکی کافی دریافت میکند. پراکسی داخلی CDP فقط روی پورت `9223` درون شبکه Compose
گوش میدهد؛ Chrome در کانتینر جانبی همچنان به رابط loopback متصل میماند.

یک اجاره ناظر در `DATA_DIR` مانع از آن میشود که چند فرایند Pusula مالک
وضعیت یکسان تونل و کارگزار شوند. هرگونه تداخل توسط ابزار بررسی سلامت گزارش میشود.

## بازیابی تعاملی

مسیر خودکار Docker هیچ پنجره قابلمشاهدهای روی میزبان ندارد، اما خود Chrome درون
نمایشگر خصوصی Xvfb در حالت دارای رابط گرافیکی اجرا میشود. هنگامی که ChatGPT به ورود تعاملی یا حل چالش نیاز دارد، میتوان از زیرساخت موجود مرورگر VNC
برای بازیابی استفاده کرد. رابط کاربری مرورگر و CDP باید فقط از طریق
loopback، یک اتصال مدیریتی احراز هویتشده یا یک تونل SSH قابل دسترسی بمانند؛ noVNC در طول
عملیات عادی غیرفعال باقی میماند.

## بازگشت به WebSocket

وقتی یک ترکیب شامل ChatGPT Web (Codex) باشد، پل Responses WebSocket پیش از اتصال به بالادست،
بازگشت به HTTP/SSE را درخواست میکند. سپس انتقال از طریق
`/v1/responses` انجام میشود.
