## نمای کلی

Search Tools Studio صفحهٔ `/dashboard/search-tools` را از یک محیط آزمایشی ساده برای جستجو به یک
استودیوی سهزبانه تبدیل میکند که جستجوی وب، استخراج محتوای وب و مقایسهٔ کنارهم ارائهدهندگان را یکپارچه میسازد.

```
┌ ابزارهای جستجو ────────────────────────────────────────────────────────┐
│ [🔍 جستجو] [📄 استخراج] [⚖ مقایسه]             142ms · $0.001  </>    │
│ ⓘ [راهنمای شیوهها]                                                    │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {محتوای زبانهٔ فعال}                    │ ─ پیکربندی                  │
│                                          │ ارائهدهنده [auto ∨]        │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (واکشی)      │
│                                          │ نوع   [وب | اخبار]          │
│                                          │ صفحهٔ کامل [ ] (استخراج)    │
│                                          │ قالب [md|متن|html]          │
│                                          │ مدل بازرتبهبندی [∨]        │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## زبانهها

### زبانه جستوجو

ترکیب موجودِ `SearchForm` + `ResultsPanel` + `RerankPanel` را به یک زبانه تبدیل میکند:

- پرسوجو ← نتایج (عنوان، URL، قطعه متن، امتیاز ارتباط).
- فراداده ارائهدهنده در پنل پیکربندی (هزینه، سهمیه، وضعیت).
- بخش بازرتبهبندی: انتخاب یک مدل بازرتبهبندی، مرتبسازی مجدد نتایج، نمایش `positionDelta`.
- حالت خالی همراه با فراخوان به اقدام، زمانی که هیچ ارائهدهنده جستوجویی پیکربندی نشده باشد.
- تاریخچه جستوجو از طریق `SearchHistory.tsx`.
- فراخوانی `POST /v1/search` (نقطه پایانی موجود، بدون تغییر).

### زبانه استخراج

زبانهای جدید برای استخراج محتوا از یک URL از طریق `POST /v1/web/fetch` (ایجادشده در برنامه 05):

- ورودی: URL + کلید تغییر وضعیت تمامصفحه + انتخابگر قالب (markdown / متن / HTML).
- ارسال ← دریافت ← رندر `ScrapeResult.tsx`.
- `ScrapeResult` پیشنمایش markdown + کلید تغییر وضعیت نمایش خام را رندر میکند.
- محدودیت: اگر بدنه پاسخ بیش از **256 KB** باشد، رابط کاربری `(کوتاهشده، مشاهده نسخه خام)` را نمایش میدهد و محتوای خام را در یک پنجره مودال Monaco باز میکند (D21).
- پنل فراداده: ارائهدهنده (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search)، تأخیر، هزینه، اندازه پاسخ، تعداد پیوندها.
- از هوک `useScrapeFetch.ts` استفاده میکند.

### زبانه مقایسه

یک پرسوجو/URL یکسان را بهصورت موازی روی حداکثر **4 ارائهدهنده** اجرا میکند (D22):

- ستونهای کنار هم برای هر ارائهدهنده.
- معیارها: تأخیر، هزینه، تعداد نتایج، اندازه پاسخ.
- محاسبه همپوشانی URLها برای جستوجو (تعداد URLهای مشترک در مقایسه با نتیجه اولیه).
- برای هر ارائهدهنده، `POST /v1/search` (جستوجو) یا `POST /v1/web/fetch` (استخراج) را فراخوانی میکند.

## پنل پیکربندی (مشترک)

`SearchToolsConfigPane.tsx` — همیشه قابل مشاهده و جمعشدنی است.

| فیلد            | توضیحات                                                                               |
| --------------- | ------------------------------------------------------------------------------------- |
| ارائهدهنده      | فهرست کشویی همراه با نشان وضعیت (پیکربندیشده / موجود نیست / دارای محدودیت نرخ)        |
| نوع             | `web` یا `news` (فقط جستجو)                                                           |

| مدل بازرتبهبندی | مدل اختیاری برای بازرتبهبندی پس از جستجو                                              |
| تاریخچه         | بخش جمعشدنی تاریخچهٔ جستجو                                                            |

## SearchConceptCard

`SearchConceptCard.tsx` — همیشه قابل مشاهده، آکاردئونی و جمعشونده. موارد زیر را توضیح میدهد:

| مفهوم                  | توضیح کوتاه                                                               |
| ---------------------- | ------------------------------------------------------------------------- |
| **جستوجو**             | فهرستی از نتایج وب (عنوان، URL، خلاصه و امتیاز مرتبطبودن) را دریافت میکند |
| **استخراج**            | محتوای کامل یک URL را استخراج میکند (markdown، متن یا HTML)               |
| **مقایسه**             | یک کوئری یکسان را بهصورت همزمان در N ارائهدهنده اجرا میکند                |
| **رتبهبندی مجدد**      | برای بهبود ارتباط با کوئری، نتایج را با استفاده از LLM دوباره مرتب میکند  |
| **خودکار (ارزانترین)** | ارزانترین ارائهدهنده موجود را بهطور خودکار انتخاب میکند                   |

## فهرست ارائهدهندگان

`ProviderCatalog.tsx` فهرست کامل ارائهدهندگان را از `GET /api/search/providers` در دسترس قرار میدهد
(در F4 گسترش یافته است تا ارائهدهندگان واکشی را نیز شامل شود):

| `kind` | `"search"` (۲۰ ارائهدهنده) یا `"fetch"` (firecrawl، jina-reader، tavily-search، tinyfish، nimble-search، anysearch-search، parallel-search) |

وضعیت **هنگام درخواست محاسبه میشود**؛ به این صورت که بررسی میشود آیا اطلاعات احراز هویت موجود است و آیا
همه کلیدها در حال حاضر در دوره انتظار مجدد هستند.

## خروجیگرفتن از کد

`ExportCodeModal` (واردشده از Playground Studio) بههمراه `codeExport.ts`، قطعهکدهای
curl / Python / TypeScript را برای فراخوانیهای `/v1/search` و `/v1/web/fetch` تولید میکنند.
مقدار جایگزین کلید API همیشه `$PUSULA_API_KEY` است (D11، مشترک با Playground Studio).

## تغییرات بکاند

برای این قابلیت فقط یک تغییر در بکاند لازم بود:

### توسعهیافته `GET /api/search/providers`

فایل `src/app/api/search/providers/route.ts` توسعه داده شد تا:

- همه ارائهدهندگان واکشی (`firecrawl`، `jina-reader`، `tavily-search`، `tinyfish`، `nimble-search`، `anysearch-search`، `parallel-search`) را در آرایه قرار دهد.
- مقدار `kind: "search" | "fetch"` را به هر مورد اضافه کند.
- مقدار `status: "configured" | "missing" | "rate_limited"` را که از وضعیت فعلی اعتبارنامهها استخراج میشود، اضافه کند.
- سازگاری با نسخههای قبلی را حفظ کند — فیلدهای موجود (`id`، `name` و غیره) بدون تغییر باقی بمانند.
