## چیست

Local Corpus به یک اپراتور اجازه میدهد یک دایرکتوری از فایلهای متنی را که بهطور صریح تأیید شده است، در اختیار سرور MCP متعلق به Pusula قرار دهد. فایلها در دایرکتوری اصلی خود باقی میمانند: Pusula فقط مسیر ریشهٔ کانونی را در SQLite ذخیره میکند و یک نمایهٔ جستوجوی درونحافظهای نگه میدارد. محتوای پیکره در مخزن یا پایگاه داده کپی نمیشود.

تازهسازی نمایه بهصورت افزایشی انجام میشود. فایلهای بدون تغییر بر اساس اندازه و زمان تغییر دوباره استفاده میشوند، فایلهای تغییرکرده مجدداً خوانده شده و با SHA-256 هش میشوند، و فایلهای حذفشده از نمایه کنار گذاشته میشوند. جستوجو نمایهای را که بیش از ۳۰ ثانیه از عمر آن گذشته باشد تازهسازی میکند؛ فراخوانها همچنین میتوانند تازهسازی فوری درخواست کنند.

## پیکربندی منبع

مسیر تنظیمات به همان احراز هویت مدیریتی موردنیاز سایر APIهای تنظیمات نیاز دارد. مسیر ارسالی باید از قبل وجود داشته باشد و یک مسیر مطلق دایرکتوری باشد.

```bash
# اتصال یک دایرکتوری تأییدشده
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# بررسی پیکربندی و وضعیت نمایه
curl http://localhost:20128/api/settings/local-corpus

# قطع اتصال بدون تغییر فایلهای منبع
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## ابزارهای MCP

هر سه ابزار به `read:local-corpus` نیاز دارند. پاسخهای ابزارها مسیرهای نسبی و نام پایهٔ دایرکتوری ریشه را نمایش میدهند و هرگز مسیر مطلق آن را افشا نمیکنند.

| ابزار                 | توضیحات                                                                        |
| :-------------------- | :----------------------------------------------------------------------------- |
| `local_corpus_status` | گزارش وضعیت پیکربندی، اندازهٔ نمایه، محدودیتها و زمان آخرین تازهسازی           |
| `local_corpus_search` | جستوجوی متن نمایهشده و بازگرداندن قطعههای محدودشده در سطح خط (حداکثر ۲۰ نتیجه) |
| `local_corpus_read`   | خواندن یک محدودهٔ محدود از خطوط یک فایل مجازِ نسبی به پیکره                    |

نمونهٔ ورودیهای MCP:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## مرزهای ایمنی

- فهرست مجاز بر متن متمرکز است: `.cfg`، `.csv`، `.geojson`، `.htm`، `.html`، `.ini`،
  `.js`، `.json`، `.jsonl`، `.jsx`، `.log`، `.md`، `.mjs`، `.ps1`، `.py`، `.sh`،
  `.sql`، `.toml`، `.ts`، `.tsx`، `.txt`، `.xml`، `.yaml` و `.yml`.
- پیوندهای نمادین نادیده گرفته میشوند. مسیرهای خواندن کانونیسازی میشوند و باید درون ریشهٔ
  پیکربندیشده باقی بمانند؛ مسیرهای مطلق و تلاشهای پیمایش مسیر رد میشوند.
- نام دایرکتوریهای حساس و تولیدشده مستثنا هستند: `.build`، `.codex`، `.env`،
  `.git`، `.next`، `.pusula`، `.ssh`، `coverage`، `dist`، `node_modules` و
  `secrets`.
- محدودیتهای پیشفرض عبارتاند از ۵٬۰۰۰ فایل، ۱ MiB برای هر فایل، ۶۴ MiB مجموع محتوای نمایهشده،
  تقریباً ۴٬۰۰۰ نویسه برای هر قطعهٔ جستوجو و ۴۰۰ خط برای هر خواندن.
- فایلهای حاوی NUL غیرمتنی در نظر گرفته میشوند و نادیده گرفته یا رد میشوند.

اسناد دودویی مانند PDF، DOCX، تصاویر و بایگانیها عمداً پشتیبانی نمیشوند.
پیش از نمایهسازی، آنها را در دایرکتوری پیکربندیشده به یک قالب متنی تأییدشده تبدیل کنید.

## نکات عملیاتی

- تغییر یا حذف ریشهٔ پیکربندیشده، نمایهٔ درونحافظهای مشترک را پاک میکند.
- راهاندازی مجدد فرایند نمایه را حذف میکند؛ جستوجوی بعدی آن را از منبع پیکربندیشده
  بازسازی میکند.
- `local_corpus_status` اسکن را اجباری نمیکند. هنگامی که اسکن مجدد فوری لازم است، از `local_corpus_search` با
  `refresh: true` استفاده کنید.
- خطاهای اسکن و خواندن شمارش میشوند یا بهصورت خطاهای پالایششده بازگردانده میشوند؛ فایلهای منبع
  هرگز تغییر داده نمیشوند.
