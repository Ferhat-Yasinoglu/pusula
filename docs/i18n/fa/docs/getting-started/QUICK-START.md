# Quick Start: Get Pusula Running in 3 Minutes (فارسی)

🌐 **Languages:** 🇺🇸 [English](../../../../getting-started/QUICK-START.md) · 🇩🇪 [de](../../../de/docs/getting-started/QUICK-START.md) · 🇹🇷 [tr](../../../tr/docs/getting-started/QUICK-START.md)

> **خلاصه**: نصب کنید → یک ارائهدهنده واجد شرایط را متصل کنید → IDE خود را به Pusula هدایت کنید. تمام.

---

## مرحله ۱: نصب Pusula

روش دلخواه خود را انتخاب کنید:

### گزینه A: npm (پیشنهادشده)

```bash
npm install -g pusula
```

### گزینه B: Docker

```bash
docker run -d --name pusula -p 20128:20128 ferhat-yasinoglu/pusula:latest
```

`:latest` بالاترین نسخه پایدار SemVer **منتشرشده** است. این تگ شاخه `main` در git را دنبال **نمیکند**. برای GitOps، نسخه `ferhat-yasinoglu/pusula:X.Y.Z` را ثابت کنید. به [تگهای ایمیج / کانالهای انتشار](../guides/DOCKER_GUIDE.md#release-channels) مراجعه کنید.

### گزینه C: از کد منبع

```bash
git clone https://github.com/Ferhat-Yasinoglu/pusula.git
cd Pusula
npm install
npm run dev
```

---

## مرحله ۲: اجرای Pusula

```bash
pusula
```

Pusula در `http://localhost:20128` اجرا میشود. داشبورد بهطور خودکار باز خواهد شد.

---

## مرحله ۳: اتصال یک ارائهدهنده واجد شرایط

ارائهدهندهای را انتخاب کنید که شرایط و سهمیهاش متناسب با نیازهای شما باشد. در **داشبورد ← ارائهدهندگان**، حساب یا کلید API خود را متصل کنید و سپس اتصال را آزمایش کنید. دسترسی رایگان و امکان استفاده بدون کلید تضمینشده نیست.

`auto` بهطور پیشفرض ارائهدهندگانی را که با `tos: avoid` علامتگذاری شدهاند، از جمله Kiro، مستثنی میکند. اتصال یک حساب این خطمشی را تغییر نمیدهد. اعلام رضایت در **داشبورد ← ترکیبها** برای همه ترکیبهای خودکار اعمال میشود. پیش از انتخاب ارائهدهنده، [راهنمای سطوح رایگان](./FREE-TIERS-GUIDE.md) را مرور کنید.

---

## مرحله ۴: اطمینان از عملکرد صحیح

از بخش [API Keys](http://localhost:20128/dashboard/api-manager)، یک کلید جدید ایجاد کنید. این کلید را ذخیره کنید، زیرا دوباره نمایش داده نخواهد شد. توجه داشته باشید که این کلید برای دسترسی ابزارها به Pusula است، نه برای دسترسی به ارائهدهندگان بالادستی.

```bash
curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_KEY"
```

باید فهرست مدلهای متصلشده خود را ببینید.

---

## مرحله ۵: اتصال IDE یا CLI به Pusula

در ابزار IDE یا CLI خود، مقادیر زیر را تنظیم کنید:

```
Base URL: http://localhost:20128/v1
API Key:  [copy from Dashboard → Endpoints]
Model:    auto
```

تمام! اکنون IDE شما با انتخاب خودکار ارائهدهنده از Pusula استفاده میکند.

### نمونه IDE: VSCode/Continue.dev

1. در VSCode، افزونه [Continue.dev](https://marketplace.visualstudio.com/items?itemName=Continue.continue) را نصب کنید.
2. فایل `~/.continue/config.yaml` خود را بهروزرسانی کرده و خطوط زیر را اضافه کنید:

```
  - name: Pusula - Auto
    provider: openai
    model: auto
    apiBase: http://localhost:20128/v1
    apiKey: <YOUR_KEY>
```

3. در پنل گفتوگوی Continue.dev، گزینه `Pusula - Auto` را انتخاب کنید تا درخواستها به Pusula ارسال شوند.
4. (اختیاری) تمرینی برای خواننده: از IDE خود بخواهید فایل `config.yaml` را با سایر پیکربندیهای ازپیشساختهشده بهروزرسانی کند 😊

### نمونه CLI: Codex CLI

1. در سیستمعامل خود، متغیر محیطی را بهصورت دائمی تنظیم کنید.
   برای macOS/Linux (آن را به `~/.bashrc` یا `~/.zshrc` اضافه کنید):

```bash
export PUSULA_API_KEY="<YOUR_KEY>"
```

برای Windows (Command Prompt):

```
setx PUSULA_API_KEY <YOUR_KEY>
```

2. اکنون Codex را با پیکربندی مخصوص Pusula اجرا کنیم. دستور زیر را اجرا کنید:

```
pusula launch-codex --model auto
```

میتوانید این کار را بهصورت دستی با `codex` و پارامترهای خط فرمان برای مشخصکردن endpoint و کلید API انجام دهید، اما با دستور بالا، Pusula همهچیز را برای شما مدیریت میکند.

همین اجرای تکدستوری برای سایر CLIها نیز از طریق اجراکننده عمومی امکانپذیر است—`pusula run <target>` از `claude`، `codex`، `aider`، `goose`، `opencode`، `qwen` و `gemini` پشتیبانی میکند (به [یکپارچهسازیهای CLI](../guides/CLI-INTEGRATIONS.md) مراجعه کنید).

3. اکنون CLI باید درخواستها را به Pusula ارسال کند.

### تأیید هدایت ابزار شما به Pusula

میتوانید با کلیک روی [Monitoring/Logs](http://localhost:20128/dashboard/logs) در نوار کناری سمت چپ، جزئیات درخواست را مشاهده کنید. با کلیک و ورود به هر مورد، جزئیات بیشتری نمایش داده میشود. همچنین میتوانید ببینید چه اطلاعاتی از ابزار موردعلاقهتان ارسال میشود. این قابلیت از دیدگاه آموزشی و اشکالزدایی مفید است.

## پرسشهای متداول

### «آیا به کلید API نیاز دارم؟»

کلید API ‏Pusula ابزارهای شما را احراز هویت میکند. اطلاعات ورود سرویسهای بالادستی به ارائهدهنده بستگی دارد: برخی به کلید API یا ورود به حساب کاربری نیاز دارند. دسترسی رایگان تضمینشده نیست.

### «`auto` چیست؟»

`auto` به Pusula میگوید که برای هر درخواست، بهترین ارائهدهنده را بهطور خودکار انتخاب کند. این انتخاب با درنظرگرفتن سرعت، هزینه، کیفیت و دسترسپذیری انجام میشود. برای جزئیات، [راهنمای Auto-Combo](./AUTO-COMBO-GUIDE.md) را ببینید.

### «هزینه آن چقدر است؟»

خود Pusula **رایگان و متنباز** است. شما فقط هزینه ارائهدهندگانی را میپردازید که استفاده میکنید. بسیاری از ارائهدهندگان سطح استفاده رایگان دارند — [راهنمای سطوح رایگان](./FREE-TIERS-GUIDE.md) را ببینید.

### «آیا میتوانم از آن با Claude Code / Cursor / Copilot استفاده کنم؟»

**بله!** Pusula با هر ابزاری که از قالب OpenAI پشتیبانی کند، کار میکند. کافی است URL پایه را روی `http://localhost:20128/v1` تنظیم کنید. برای دستورالعملهای راهاندازی هر ابزار، [راهنمای ابزارهای CLI](../reference/CLI-TOOLS.md) را ببینید.

### «اگر یک ارائهدهنده از دسترس خارج شود، چه اتفاقی میافتد؟»

Pusula بهطور خودکار از ارائهدهندگان ناموفق عبور میکند و ارائهدهنده بعدی را امتحان میکند. لازم نیست کاری انجام دهید. برای جزئیات، [راهنمای Auto-Combo](./AUTO-COMBO-GUIDE.md) را ببینید.
