# Thinking Budget (فارسی)

🌐 **Languages:** 🇺🇸 [English](../../../../guides/THINKING_BUDGET.md) · 🇩🇪 [de](../../../de/docs/guides/THINKING_BUDGET.md) · 🇹🇷 [tr](../../../tr/docs/guides/THINKING_BUDGET.md)

---

> **داشبورد:** تنظیمات ← **هوش مصنوعی** ← بودجه تفکر  
> **API:** `GET` / `PUT` `/api/settings/thinking-budget`  
> **منبع:** `open-sse/services/thinkingBudget.ts`

بودجه تفکر تعیین میکند که آیا Pusula **پارامترهای تفکر/استدلال کلاینت را** در مسیر ارسال به ارائهدهندگان بازنویسی کند یا خیر. این تنظیم، فشردهسازی، مسیریابی یا کش پرامپت را فعال یا غیرفعال **نمیکند**.

## حالتها

| حالت                       | کاری که Pusula انجام میدهد                                                                                                          | زمان استفاده                                                                                                                                                              |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`passthrough`** (پیشفرض) | فیلدهای کلاینت را بدون تغییر باقی میگذارد (`reasoning`، `reasoning_effort`، `thinking` در Claude، `thinking_config` در Gemini و غیره). | **Codex / Desktop / هر کلاینتی که باید میزان تلاش و خلاصههای استدلال را کنترل کند.** برای نمایش پنلهای تفکر، وقتی کلاینت `reasoning.summary` را درخواست میکند، ضروری است. |
| **`auto`**                 | پیش از ارسال به بالادست، **تمام** فیلدهای تفکر/استدلال را از بدنه درخواست حذف میکند.                                                   | فقط زمانی که عمداً میخواهید **ارائهدهنده** مقادیر پیشفرض را تعیین کند و نیازی به تفکر کنترلشده توسط کلاینت ندارید. این حالت بهمعنای «نمایش خودکار تفکر» **نیست**.         |
| **`custom`**               | تمام درخواستها را با یک بودجه ثابت برای توکنهای تفکر بازنویسی میکند.                                                                   | تعیین سقف سخت برای توکنهای تفکر در تمام ترافیک.                                                                                                                           |
| **`adaptive`**             | بودجه را بر اساس میزان تلاش پایه و با استفاده از تعداد پیامها، ابزارها و طول پرامپت مقیاسبندی میکند.                                   | کنترل نرم توکنها، بدون حذف کامل هدف کلاینت.                                                                                                                               |

### مواردی که `auto` حذف میکند

وقتی حالت روی `auto` تنظیم شده باشد، `stripThinkingConfig()` موارد زیر را (در میان سایر موارد) حذف میکند:

- OpenAI / Responses: `reasoning`، `reasoning_effort`
- Claude: `thinking` و، در صورت وجود، `output_config.effort`
- Gemini: `generationConfig.thinking_config` / `thinkingConfig`

اگر کلاینتی (برای مثال Codex Desktop) مقدار `reasoning: { effort: "ultra", summary: "detailed" }` را ارسال کرده باشد، حالت **auto آن شیء را حذف میکند**. بالادست ممکن است همچنان بابت تعدادی توکن استدلال هزینه دریافت کند، اما اغلب آیتمهای استدلال **خالی یا صرفاً رمزگذاریشده** را بازمیگرداند؛ بنابراین رابط کاربری هیچ جریان تفکر مفیدی را نمایش نمیدهد.

## مواردی که این تنظیم **نیست**

| قابلیت                                        | ارتباط                                                                                                                                          |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **فشردهسازی** (Caveman، RTK، stacked و …)     | خط پردازش جداگانهای است. در تمام حالتهای بودجه تفکر کار میکند.                                                                                  |
| **کش پرامپت / معنایی**                        | جداگانه است. تحت تأثیر حالت بودجه تفکر قرار نمیگیرد.                                                                                            |
| **مسیریابی ترکیبی / مسیرهای جایگزین**         | جداگانه است. تحت تأثیر قرار نمیگیرد.                                                                                                            |
| **محدودیتهای توکن کلید API / بودجههای هزینه** | جداگانه است. تحت تأثیر قرار نمیگیرد.                                                                                                            |
| **کش بازپخش استدلال**                         | تزریق مجدد چندمرحلهای برای ارائهدهندگان سختگیر (DeepSeek، Kimi، Qwen-thinking و …). با «نمایش تفکر» در Desktop یکسان نیست.                      |
| **رمزگشایی `encrypted_content`**              | **غیرممکن است.** دادههای خصوصی استدلال OpenAI/Codex مبهم و غیرقابلخواندن هستند. Pusula هرگز آنها را رمزگشایی نمیکند (#7095 / #7176 / #7304). |

## نمایش تفکر (کلاینتهای Codex / Responses)

برای اینکه یک کلاینت متن تفکر را نمایش دهد، به **همه** موارد زیر نیاز دارید:

1. حالت Thinking Budget برابر با **`passthrough`** باشد (یا حالت سفارشی/تطبیقی که درخواستهای خلاصه را برای مسیر مورد استفاده شما بهاندازه کافی دستنخورده نگه دارد).
2. کلاینت درخواست خلاصه کند؛ برای مثال، در Codex مقدار `model_reasoning_summary = "detailed"` / `auto` باشد (نه `none`).
3. سرویس بالادستی واقعاً `response.reasoning_summary_text.*` را بهصورت جریانی ارسال کند (یا آیتم دارای `reasoning.summary` غیرخالی باشد).

اگر فقط «استدلال خصوصی رمزگذاریشده» دریافت میکنید، یکی از این موارد رخ داده است:

- حالت **`auto`** بوده است (درخواست کلاینت حذف شده)، یا
- سرویس بالادستی `encrypted_content` را بدون متن خلاصه برگردانده است (محدودیت ارائهدهنده؛ Pusula فقط میتواند یک جاینگهدار نمایش دهد، نه متن ساده).

## نمونههای API

```bash
# خواندن
curl -sS https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $PUSULA_TOKEN"

# توصیهشده برای مشاهدهپذیری تفکر در Codex / Desktop
curl -sS -X PUT https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $PUSULA_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"mode":"passthrough","customBudget":10240,"effortLevel":"medium"}'
```

شِما (`updateThinkingBudgetSchema`): `mode` ∈ `passthrough|auto|custom|adaptive`؛ گزینههای اختیاری: `customBudget`، `effortLevel`، `baseBudget`، `complexityMultiplier`.

### ماندگاری / راهاندازی مجدد

مقدار تحت کلید تنظیمات `thinkingBudget` ذخیره میشود و هنگام شروع فرایند بارگذاری میشود (`hydrateThinkingBudgetConfig`). پس از تغییر از طریق DB یا برخی مسیرهای غیر API، **فرایند Pusula را مجدداً راهاندازی کنید** تا سینگلتون درون حافظه با دادههای روی دیسک مطابقت داشته باشد.

## چکلیست اپراتور

- [ ] کاربران Codex / Desktop: حالت = **passthrough**
- [ ] اگر میخواهید با فشردهسازی **پیامها** در توکنها صرفهجویی کنید، فشردهسازی را همچنان فعال نگه دارید، نه اینکه تفکر را حذف کنید
- [ ] انتظار نداشته باشید `auto` «تفکر بیشتری نمایش دهد»
- [ ] خلاصههای صرفاً رمزگذاریشده، رفتار **ارائهدهنده** هستند؛ passthrough نمیتواند آنها را رمزگشایی کند
